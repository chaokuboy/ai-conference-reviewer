# 创新工作台

本文件为 S：研究设计综合方法，不是任何会议独有政策。

## 从想法到可证伪主张

先用一句话恢复用户意图：“在条件 X 下，现有方法因 Y 失效，我们通过 Z 改善 Q，且代价为 C。”不要求所有论文采用方法创新：分析、理论、资源和负结果可替换这句话中的动作。
没有数据时提出假说，不写成已经发现。先记录可用算力、数据权利、时间和合作者专长，再决定方案。

逐轮追问优先顺序可随材料调整：

1. 谁面临什么确实存在的问题？是结果差，还是测量了错误的目标？
2. 最强的现成办法为什么不能解决？有观察证据还是直觉？
3. 你的变化究竟在目标、假设、方法、测量还是资源？
4. 哪个结果出现就说明核心解释不成立？
5. 去掉新名词、新模块和大模型规模后，还剩什么贡献？

## 最近邻比较

通常查最接近的 3–5 篇；数量由实质覆盖决定。分别找同任务、同机制、同评测、最强简单替代方案。阅读一手正文后才判断机制重复；标题摘要仅作筛选。

记录：论文与公开版本日期｜问题／假设｜方法｜数据与算力｜核心结论｜与本稿同与不同｜已读范围。标注已发表、预印本、同期工作，结合当届规则决定比较义务。

创新不是“没有检索到同名论文”。新缩写、组件排列、换语言／领域、增加模型大小都需要说明新增知识；也不能因为是组合、单语言或复现就否定价值。

## 可选择的贡献路径

| 路径 | 有价值的差异 | 最小判别证据 | 常见失败模式 |
|---|---|---|---|
| 新问题／任务 | 暴露旧设定漏掉的实际约束 | 真实需求或失败案例；证明现有任务不能等价覆盖 | 仅给旧任务改名 |
| 方法 | 对已确认瓶颈提出有理由的改动 | 强简单基线、预算匹配、拆除关键机制的对照 | 提升源自更多调用或更多数据 |
| 理论 | 更弱假设、更紧界、新解释或反例 | 完整证明、适用边界、与最近定理的直接比较 | 结论换符号；假设排除了所声称场景 |
| 经验发现 | 揭示稳定、重要而未被建立的现象 | 排除测量偏差和替代解释；适当外部验证 | 把相关性或单模型异常包装成机制 |
| 数据／评测 | 测到现有资源遗漏的重要能力 | 构念效度、质量审计、泄漏检查、基线及用途 | 大规模自动生成且未验证标注 |
| 效率／系统 | 在明确约束下改善质量—成本权衡 | 同条件 Pareto 曲线、端到端成本和复现细节 | 只报理论 FLOPs 或忽略检索／生成费用 |
| 负结果／复现 | 改变社区对某方法何时有效的认识 | 合理实现和调参、反例边界、替代原因排查 | 一次训练失败即普遍否定 |
| 应用驱动 | 应用约束催生新的技术或问题认识 | 约束真实性、领域有效指标与强替代方案 | 换数据集套现成方法 |

## 设计候选路线

给 2–3 条实质不同路线，而不是十个组合标题。每条包括：

- 核心主张与最接近工作；
- 最便宜的反证实验；
- 若通过再投入的决定性验证；
- 资源与访问前提；
- 失败后的诚实出口（缩小主张、分析贡献、停止），不事后改故事隐藏失败。

按“重要性、可区分性、可验证性、资源适配”定性比较。资源不够时缩小能支持的主张，不许诺一定能投顶会。

## 示例：多智能体审稿是否是创新？

输入：“多个 agent 讨论后能提高审稿质量，想投 ACL 或 ICLR。”
首先不认定多 agent 本身新颖。候选路线：

- 评价创新：把质量拆为事实正确、证据定位、遗漏与无效批评；验证评价器，而非仅与人类总分相关。
- 机制研究：检验讨论是否纠正错误或放大共同偏差；对比独立聚合、单模型多次采样，匹配 token／调用预算。
- 方法创新：针对可定位的证据错误做检索或验证机制；比较同预算、不带该机制的系统。

人工评估应盲化系统身份，规定评分准则，报告分歧；划分论文与评审数据，防止训练／提示示例污染测试。以上均是待检验方案，没有虚构实验结果。
