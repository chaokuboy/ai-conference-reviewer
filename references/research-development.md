# 研究升级与验证决策

本文件为 S：帮助用户发展贡献和证据的综合研究方法；候选解释与未完成方案为 H。它不是 A 会录用标准或成功保证。按用户请求只使用相关模块，不强制每次跑完六步。会议契合度用 [会议画像](venues.md)，官方资格用 [投稿检查](submission.md)，均不由本文件替代。

## 输入与执行边界

从已有想法、稿件、最近邻、结果和资源开始。记录目标贡献、已知事实、当前最大不确定性、算力／API 预算、数据访问、期限和研究阶段；缺信息先注明假设，只追问会改变当前方案的关键项。用户只问一个实验时直接处理该实验。

“设计实验”不表示实验已运行；“结果分析”只基于实际提供或在授权范围内得到的数据。规划不会自动授权付费计算、外传稿件或投稿。无法估算成本时给计算方法与待确认参数，不虚构 GPU 小时或费用。

## 1. 研究差距诊断

先读 [证据审查](evidence-review.md)，涉及创新再读 [创新工作台](innovation.md) 的最近邻比较。按主张找差距，不给论文套统一分数或把应用、组合与复现自动判成低价值。

依次区分适用的问题：问题本身是否重要且有依据？相对前作究竟增加什么？证据是否能排除替代解释？当前证据允许多宽的结论？目标读者为何需要这个结果？缺材料时保留待确认。

输出简短差距卡：

> 当前贡献与材料位置｜最有价值的部分｜决定性缺口及影响｜可保留的工作｜需补证据或重新设计的部分｜下一项最小行动。

每项缺口注明是观察到的问题还是材料未覆盖。若问题只在表达，不建议重跑全部实验；若科学主张失效，不用改摘要掩盖。科学价值与会议契合度分开，不将文献未查证解释成创新不足。

## 2. 创新路线升级

贡献路径、最近邻记录和候选方案字段统一使用 [创新工作台](innovation.md)，此处只增加路线选择决策。

围绕已发现的瓶颈，按需提出通常 2–3 条实质不同路线：改变研究问题或假设、区分竞争性机制、设计有依据的方法、改进测量效度、建立理论结果或刻画负结果边界。新模块必须说明针对哪个瓶颈；换领域也应说明新约束或新增认识，不能仅换叙述。

每条路线给出：

> 相对最近邻的候选差异（已核验／暂定）｜为什么重要｜成立前提｜最小判别验证｜通过后投入什么｜失败后如何缩小主张或停止｜资源与目标读者。

按知识增量、区分竞争解释的能力、验证可行性与资源适配比较，说明首选理由及何种证据会改变选择。不把所有优点合成貌似客观的“顶会潜力分”。已有明确路线时只深化或指出决定性风险。

## 3. 实验方案改良

先按 [证据审查](evidence-review.md) 确定贡献类型和实际主张。理论、position 或概念研究使用证明、反例、论证审查等适当验证，不强制模型实验。

实证方案按需求填写以下字段；每一项必须服务于一个判断：

| 字段 | 设计要求 |
|---|---|
| 问题与假说 | 区分目标主张与竞争解释；写出何种观察能区分二者 |
| 比较对象 | 最近邻、强简单替代与必要消融；说明各自排除什么解释，不要求穷尽模型 |
| 控制与预算 | 控制相关数据、调参、计算和信息访问；无法同时匹配的条件明确报告，必要时分别比较 |
| 数据与划分 | 明确分析单位、抽样范围、训练／开发／测试隔离、泄漏风险及排除规则；有聚类或重复测量时按对应单位处理 |
| 指标与测量 | 主指标对应主张；辅助指标解释收益与代价。涉及真实质量或偏好时核验评价器效度 |
| 不确定性 | 根据效应、变异层级和成本决定样本与重复；数据不足先做小规模估计，不默认固定种子数或套不适用的检验 |
| 决策条件 | 事前提出有研究意义的效应范围、失败条件和预算上限；未知阈值标为待校准，不能看到测试结果后选最有利阈值 |
| 执行与产物 | 数据／实现依赖、运行顺序、预算估算依据、结果表及必要日志；记录失败运行与协议变更 |

预算可表示为“配置数 × 重复数 × 每次测量成本＋必要预处理与评估费用”，注明哪些参数未知。核心结论已足够支持时不为了凑清单增加实验。

执行优先级：先验证数据和测量是否可信，再做最能推翻核心解释的低成本对照；通过后投入决定性验证，最后按主张需要扩展范围。将核心证据、稳健性检查和可选拓展分开。

典型改良：多 agent 优于单次调用时增加同预算单模型采样；消融同时改变计算量时补匹配计算的对照；仅在某个硬件成立的效率结果限定条件。改良理由必须落在当前稿件，不能照搬例子。

## 4. 结果驱动的下一步

先记录实际结果来源、实验版本、覆盖范围与不确定性，再更新主张—证据状态；没有结果时只交付条件式决策树。使用下表时依据实际效应与协议，不把“不显著”直接等同于无效。

| 观察 | 决策方向 |
|---|---|
| 收益存在，关键控制后仍保留 | 检查机制解释还剩哪些竞争假说；仅在主张需要时扩展覆盖 |
| 同预算强简单基线消除收益 | 降低对新机制的支持；核查是否仍有独立成本或适用性贡献，否则重设或停止 |
| 仅某个子群／条件有效 | 先检查测量与选择偏差；候选边界分析标为探索性，再用独立数据或适当验证确认 |
| 区间宽、方向不稳定 | 定位变异层级，评估再采样能否改变决策；预算不支持时保留不确定结论 |
| 可靠结果与核心主张冲突 | 撤回或收缩该主张；只有新增知识得到支持时才发展负结果贡献 |
| 测量、泄漏或实现有问题 | 暂停科学解释，修正受影响流程并重测；旧结果保留失效标记 |

项目记录包含原假说、观察、更新后的判断、下一行动与停止理由。探索性发现不能伪装成预先假说；反复用测试集选方案后，应披露并安排独立确认，不能继续称它为未触碰测试集。

## 5. 贡献与论文论证

把已支持的知识增量组织成“问题 → 前作局限 → 本文差异 → 决定性证据 → 适用边界”。路径可随贡献类型调整；写作不是把未经验证的想法包装成贡献。

输出主张—图表／证明映射：

> 主张及限定条件｜最近邻差异｜实际证据位置｜关键展示｜已排除与尚存的解释｜应写出的限制。

每个贡献点都应表达新增认识或能力，不只列模块和工作量。现有图表与拟制作图表分开；没有结果时提供空白结构或注明示意，不生成貌似真实的数据。摘要、引言和结论使用一致的主张范围；只观察相关性时不改写成因果。

可建议关键图表的目的，如展示同预算差异或失败条件，但不预设曲线形状。若用户只需要论证修改，优先利用已有证据并说明仍无法支持的句子。

## 6. 投稿成熟度复查

成熟度不是录用预测。分别给出科学证据、会议／track 契合度和行政资格三个结论。按 [证据审查](evidence-review.md) 核查主张，按 [投稿检查](submission.md) 核验动态政策；需要模拟评审时再读 [审稿与回复](review-rebuttal.md)。

将事项分成：

- 必须解决：有依据且影响核心结论的可靠性或证据问题，以及已核验的投稿硬性要求。
- 可修复表达：现有证据支持，但论证、定位或复现说明不清晰。
- 可选拓展：不影响现有主张，只扩大范围或提升便利性。
- 待确认：材料未覆盖、最近邻未核验或政策未核对；不填成“通过”。

给出当前可支持的贡献、最重要的未解决事项、完成判据、依赖和资源。可判断“可进入投稿准备”“需补核心验证”“需重新设计”或“材料不足以判断”，必须解释依据；这些是工作安排，不是通用会议门槛。新结果出现后重新检查，已解决的问题不自动保留。
