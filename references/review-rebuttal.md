# 模拟审稿与回复

以下为 S 工作流。模拟角色只是分析视角，不代表独立人类评审或真实委员会意见。

## 审稿模式

先读目标会议当届官方表单，再决定是否输出其评分项；无法核验量表时用文字判断，不把不同会议分数通用化。用户要求评分时注明模拟依据和不确定性，不换算录用概率。

根据稿件需要选择视角：贡献与最近邻、技术／证据、评估与复现。可以在一份评审中合并，不为凑三个 reviewer 重复制造缺点。

评审包含：忠实概述、最强优点、关键弱点及位置、需要回答的问题、可选改进、判断及信心依据。
总体判断必须与技术事实一致；没有足够正文不能输出貌似完整的严格审稿。

模拟 AC 的重点是解决冲突：

| 分歧 | 应如何处理 |
|---|---|
| 一位说缺实验，附件已有 | 核对附件位置与是否回答同一主张；纠正事实错误 |
| 一位重 SOTA，一位重分析 | 先定贡献类型，判断 SOTA 对实际主张是否必要 |
| 认为不新颖但无前作 | 要求可核查最近邻，不以断言当事实 |
| 回复声称已补实验但无结果 | 记为承诺或待确认，不能视为缺口已闭合 |
| 小误差与核心错误混合 | 分开可修复问题与会推翻结论的问题 |

## Rebuttal 的目标与结构

先提取每个 reviewer 的决定性问题，检查当届字数、附件、新实验、新版稿件和讨论规则。不要把 ICLR 某年的可修改机制套给其他会议或以后届次。

维护：问题 ID｜原评论｜类型｜现有证据｜回应策略｜修改位置｜状态。

- 事实误解：直接澄清，给原文位置，必要时改写正文以避免再次误读。
- 真实缺口：承认范围，提供已经完成的验证或收缩主张。
- 价值分歧：解释知识增量，与具体前作比较，不诉诸名气或热点。
- 超范围要求：说明与现有主张的关系，提供合理边界，不一概指责审稿人。
- 违规或不专业评论：若用户需要，按官方途径起草事实性说明；不自动发送。

回复段落模板：

> 感谢指出【具体问题】。我们的主张限于【范围】。【节／表】已显示【实际证据】。为消除歧义，我们【已完成的修改／拟修改，分清状态】。关于【仍未知项】，目前证据不足，因此我们将【缩小主张或说明限制】。

保留篇幅给 1–3 个关键争议；共同问题集中回答，各 reviewer 的特定问题简洁回应。不要虚构“实验已做”，也不要只说将在 camera-ready 完成核心验证。

## 修改计划

区分可在回复期澄清、需重新实验、需重新设计三层。重新设计级缺口通常应进入下一轮研究计划，不用修辞掩盖。
终稿核对摘要、引言、图表和结论的承诺一致性，更新限制及资源说明。无须把回应审稿人的对话历史写入论文。
