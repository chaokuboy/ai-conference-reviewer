# 主张—证据审查

本文件为 S：按主张选择的技术审查方法。正式会议评分维度从对应年份指南另行加载。

## 先确定贡献类型

算法、理论、分析、数据／评测、系统／效率、应用、负结果、position 的证据不同。不要求 position 凭空补模型，不因理论论文无大型实验判失败；有实证承诺才审查其兑现程度。

| 主张 | 重点核对 | 不足时的最小行动 |
|---|---|---|
| “优于现有方法” | 最接近强基线、相同数据／预算、调参公平、指标方向 | 补最能推翻结论的基线，不盲目补所有模型 |
| “来自机制 M” | 可隔离 M 的干预，是否同时改变数据、计算或架构 | 做单因素或有解释力的组合对照；消融不自动等于因果机制证明 |
| “稳健／泛化” | 留出划分、分布变化、样本选择与主张范围 | 补关键分布外测试或缩窄主张 |
| “更高效” | 与所声称成本对应的测量、硬件与质量条件；端到端主张须计入相关开销 | 固定条件改进用匹配条件对照；权衡优势用质量—成本曲线 |
| “更可靠／公平” | 风险定义、分组样本、错误成本、不确定性 | 明确指标效度及受影响人群 |
| “评价人类偏好／质量” | 评分构念、标注指引、评估者能力、盲法与分歧 | 先验证评价器，再评价方法 |
| “定理保证” | 量词、假设、证明各步、退化情况、常数与边界 | 指定无法成立的一步或条件，不泛称“证明不严谨” |
| “真实世界有效” | 实际约束、任务代理是否可信、对照与落地代价 | 验证需求和指标；不能由离线分数推断部署收益 |

## LLM／agent 研究中特别容易混淆的证据

- judge 与被评模型共源、位置偏好、长度偏好、提示敏感性：若把 judge 分数解释为真实质量或人类偏好，核对相关样本上的人类或可信标准校准；若仅研究该 judge 的评分行为，不自动要求人评，但不得外推为真实质量。
- 测试污染：追踪数据来源、时间、去重和检索索引；训练数据未知不能保证“无污染”。
- 预算：多 agent 对比单次调用会混淆架构与计算；包括失败重试、工具费用和所有采样。
- agent 成功：区分最终任务完成、过程有效、工具正确和安全限制；保存可核查轨迹，防止只挑成功案例。
- 检索／长上下文：知识可获得性、引用支撑、位置和上下文长度是不同变量。
- 统计：种子、数据实例、任务、标注者是不同变异层级。重复次数由结论稳定性和成本决定，不规定固定“三个种子”。报告有意义的区间、效应大小与失败分布。
- 闭源 API：记录模型版本、日期和参数；必要时用可访问模型做机制验证。不要把不可访问的最新闭源模型作为一概必须比较的对象。

## 诊断证据表

主张 ID｜原文位置｜范围｜材料覆盖｜证据及出处｜替代解释｜证据状态｜影响｜最小验证。

- 材料覆盖：已读正文／已读相关附件／仅摘要／未提供／未读取；按相关材料分别记录。已读论文不等于已核验代码、证明或全部补充材料。
- 证据状态：已有支持（限明确范围）、部分支持（只支持较窄范围）、支持不足（已检查相关材料但论据不足）、存在反证（指出与主张冲突的证据）、待确认（缺必要材料或核验）、不适用（与该贡献无关）。支持不足不等于结论为假，存在反证也须说明条件与可靠性。
- 影响：核心结论、局部结论、表达、可选拓展；按实际受影响的主张判定，不由状态名称自动决定拒稿。

例如：附件未提供 → 覆盖受限／待确认；检查正文与相关附件后未见跨域验证 → 跨域主张支持不足；仅域 A 有效 → 对 A 已有支持、对更广范围待确认或不足；域 B 可靠结果与“所有域改善”冲突 → 广泛主张存在反证。
位置可以是节、图表、定理、原句；没有页码就不编页码。对附件未读、证明未查、代码未运行分别披露。

区分：核心结论失效、关键证据待补、表达可修复、可选拓展。只把前两类有材料支持的问题列为已观察到的主要障碍；未读材料造成的风险单列待确认。
若用户提供了补充材料或作者回复，重新检查并更新状态；不要让旧批评在新证据出现后自动保留。
